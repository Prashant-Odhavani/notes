Angular Interview Notes — Complete Revision Guide

A single reference covering core concepts, practical code examples, and the questions interviewers actually ask. Organized so you can skim for revision or read deep for understanding.

1. Angular Fundamentals

What is Angular? Angular is a TypeScript-based, component-driven front-end framework maintained by Google for building single-page applications (SPAs). It provides built-in solutions for routing, forms, HTTP communication, and state management, unlike libraries such as React which only handle the view layer.

Key building blocks:

  • Components — control a patch of screen (UI + logic)
  • Templates — HTML with Angular-specific syntax
  • Modules (NgModules) — group related code (being phased out in favor of standalone)
  • Services — reusable business logic, injected via DI
  • Directives — add behavior to DOM elements
  • Pipes — transform data in templates

Why Angular over plain JS/jQuery?

  • Two-way data binding
  • Component reusability
  • Dependency Injection out of the box
  • Strong typing via TypeScript → fewer runtime bugs
  • CLI for scaffolding, testing, building
  • RxJS for reactive async data handling

Angular vs AngularJS

AngularJS Angular (2+)
JavaScript TypeScript
MVC based Component based
No mobile support Mobile-first
$scope, controllers Components, classes
Slower digest cycle Faster change detection

2. Architecture & Modules

NgModule example:

TypeScript
@NgModule({
  declarations: [AppComponent, HeaderComponent],
  imports: [BrowserModule, FormsModule, HttpClientModule],
  providers: [UserService],
  bootstrap: [AppComponent]
})
export class AppModule {}
  • declarations — components/directives/pipes belonging to this module
  • imports — other modules this module depends on
  • providers — services registered at module level
  • bootstrap — root component to bootstrap the app (only in root module)

Feature Modules vs Shared Modules vs Core Module

  • CoreModule — singleton services (auth, logging), imported once in AppModule
  • SharedModule — common components/pipes/directives reused across features, imported everywhere needed
  • Feature Modules — encapsulate a business feature (e.g., OrdersModule), often lazy-loaded

Lazy Loading example:

TypeScript
const routes: Routes = [
  {
    path: 'orders',
    loadChildren: () => import('./orders/orders.module').then(m => m.OrdersModule)
  }
];

Lazy loading splits the bundle so feature code downloads only when the route is visited — improves initial load time.

3. Components & Templates

Anatomy of a component:

TypeScript
@Component({
  selector: 'app-user-card',
  templateUrl: './user-card.component.html',
  styleUrls: ['./user-card.component.css']
})
export class UserCardComponent {
  @Input() user!: { name: string; email: string };
  @Output() selected = new EventEmitter<string>();

  onSelect() {
    this.selected.emit(this.user.name);
  }
}

Template:

HTML
<div class="card" (click)="onSelect()">
  <h3>{{ user.name }}</h3>
  <p>{{ user.email }}</p>
</div>

@Input / @Output — parent-child communication

HTML
<!-- Parent template -->
<app-user-card [user]="currentUser" (selected)="handleSelection($event)"></app-user-card>
  • @Input() passes data into a child component
  • @Output() + EventEmitter sends data out to the parent

ViewChild / ContentChild

TypeScript
@ViewChild('nameInput') nameInput!: ElementRef;

ngAfterViewInit() {
  this.nameInput.nativeElement.focus();
}
  • @ViewChild accesses a child component/element/directive defined in the template
  • @ContentChild accesses projected content (via <ng-content>)

Content Projection:

HTML
<!-- card.component.html -->
<div class="card"><ng-content></ng-content></div>

<!-- usage -->
<app-card><p>Anything goes here</p></app-card>

4. Data Binding

Type Syntax Direction
Interpolation {{ value }} Component → View
Property binding [property]="value" Component → View
Event binding (event)="handler()" View → Component
Two-way binding [(ngModel)]="value" Both

Two-way binding example (requires FormsModule):

HTML
<input [(ngModel)]="username" placeholder="Enter name">
<p>Hello, {{ username }}</p>

Two-way binding is syntactic sugar over:

HTML
<input [ngModel]="username" (ngModelChange)="username = $event">

Custom two-way binding (banana in a box syntax) for your own component:

TypeScript
@Input() value!: string;
@Output() valueChange = new EventEmitter<string>();

updateValue(v: string) {
  this.value = v;
  this.valueChange.emit(v);
}
HTML
<app-rating [(value)]="starRating"></app-rating>

5. Directives

Three types:

  1. Component directives — directives with a template (every @Component is technically a directive)
  2. Structural directives — change DOM layout by adding/removing elements (*ngIf, *ngFor, *ngSwitch)
  3. Attribute directives — change appearance/behavior of an element (ngClass, ngStyle, custom ones)

Structural directive examples:

HTML
<div *ngIf="isLoggedIn; else guestBlock">Welcome back!</div>
<ng-template #guestBlock><div>Please log in</div></ng-template>

<ul>
  <li *ngFor="let item of items; index as i; trackBy: trackById">
    {{ i }} - {{ item.name }}
  </li>
</ul>
TypeScript
trackById(index: number, item: any) { return item.id; }

trackBy prevents Angular from destroying/recreating DOM nodes unnecessarily when the array reference changes — a key performance optimization.

Modern control flow (Angular 17+) — replaces ngIf/ngFor:

HTML
@if (isLoggedIn) {
  <p>Welcome back!</p>
} @else {
  <p>Please log in</p>
}

@for (item of items; track item.id) {
  <li>{{ item.name }}</li>
} @empty {
  <li>No items found</li>
}

This new syntax is compiled, faster than the old structural directives, and mandates track for @for (equivalent to trackBy).

Custom Attribute Directive:

TypeScript
@Directive({ selector: '[appHighlight]' })
export class HighlightDirective {
  @Input() appHighlight = 'yellow';

  constructor(private el: ElementRef, private renderer: Renderer2) {}

  @HostListener('mouseenter') onEnter() {
    this.renderer.setStyle(this.el.nativeElement, 'backgroundColor', this.appHighlight);
  }

  @HostListener('mouseleave') onLeave() {
    this.renderer.removeStyle(this.el.nativeElement, 'backgroundColor');
  }
}
HTML
<p appHighlight="lightblue">Hover over me</p>

Use Renderer2 instead of directly manipulating nativeElement.style for platform-safety (works with server-side rendering too).

6. Pipes

Pipes transform displayed data without changing the underlying value.

Built-in pipes:

HTML
{{ price | currency:'USD' }}
{{ today | date:'mediumDate' }}
{{ name | uppercase }}
{{ user | json }}
{{ items | slice:0:3 }}

Custom Pipe:

TypeScript
@Pipe({ name: 'truncate' })
export class TruncatePipe implements PipeTransform {
  transform(value: string, limit: number = 20): string {
    return value.length > limit ? value.slice(0, limit) + '...' : value;
  }
}
HTML
<p>{{ longText | truncate:50 }}</p>

Pure vs Impure pipes:

  • Pure (default) — only re-runs when input reference changes. Efficient.
  • Impure (pure: false) — runs on every change detection cycle, even if input reference is unchanged. Needed for things like filtering a mutable array, but hurts performance if overused.
TypeScript
@Pipe({ name: 'filterList', pure: false })
export class FilterListPipe implements PipeTransform { ... }

7. Dependency Injection & Services

Why DI? Promotes loose coupling, easier testing (mock services), and single-responsibility.

Creating an injectable service:

TypeScript
@Injectable({ providedIn: 'root' })
export class UserService {
  constructor(private http: HttpClient) {}

  getUsers(): Observable<User[]> {
    return this.http.get<User[]>('/api/users');
  }
}

providedIn: 'root' registers the service as a singleton at the application root — tree-shakable, so it's removed from the bundle if unused.

Injecting into a component:

TypeScript
constructor(private userService: UserService) {}

ngOnInit() {
  this.userService.getUsers().subscribe(users => this.users = users);
}

Hierarchical injectors — Angular has a tree of injectors (root → module → component). A service provided at a component level creates a new instance for that component and its children, separate from the root singleton.

TypeScript
@Component({
  selector: 'app-widget',
  providers: [WidgetService]  // new instance scoped to this component subtree
})

Injection tokens (for non-class dependencies):

TypeScript
export const API_URL = new InjectionToken<string>('API_URL');

providers: [{ provide: API_URL, useValue: 'https://api.example.com' }]

constructor(@Inject(API_URL) private apiUrl: string) {}

Newer inject() function (Angular 14+):

TypeScript
export class UserService {
  private http = inject(HttpClient);
}

Allows DI outside constructors, useful in standalone functions and functional guards/resolvers.

8. Lifecycle Hooks

Executed in this order for every component:

Hook When it runs
ngOnChanges Before ngOnInit, and whenever an @Input value changes
ngOnInit Once, after first ngOnChanges — good for initialization/API calls
ngDoCheck On every change detection run — custom change detection logic
ngAfterContentInit After projected content (ng-content) is initialized
ngAfterContentChecked After every check of projected content
ngAfterViewInit After component's view (and child views) initialized
ngAfterViewChecked After every check of the component's view
ngOnDestroy Just before component is destroyed — cleanup (unsubscribe, clear timers)
TypeScript
export class TimerComponent implements OnInit, OnDestroy {
  private sub!: Subscription;

  ngOnInit() {
    this.sub = interval(1000).subscribe(t => console.log(t));
  }

  ngOnDestroy() {
    this.sub.unsubscribe(); // prevents memory leaks
  }
}

Interview favorite: "Why is ngOnDestroy important?" → To unsubscribe from Observables/event listeners and avoid memory leaks, since components can be destroyed (e.g., route navigation) while subscriptions remain active.

9. Routing

Basic setup:

TypeScript
const routes: Routes = [
  { path: '', component: HomeComponent },
  { path: 'users/:id', component: UserDetailComponent },
  { path: 'admin', component: AdminComponent, canActivate: [authGuard] },
  { path: '**', component: NotFoundComponent }
];

@NgModule({
  imports: [RouterModule.forRoot(routes)],
  exports: [RouterModule]
})
export class AppRoutingModule {}

Router outlet & navigation:

HTML
<a routerLink="/users/5" routerLinkActive="active">User 5</a>
<router-outlet></router-outlet>
TypeScript
constructor(private router: Router, private route: ActivatedRoute) {}

goToUser(id: number) {
  this.router.navigate(['/users', id]);
}

ngOnInit() {
  this.route.paramMap.subscribe(params => this.userId = params.get('id'));
}

Route Guards (functional style, Angular 15+):

TypeScript
export const authGuard: CanActivateFn = (route, state) => {
  const auth = inject(AuthService);
  const router = inject(Router);
  return auth.isLoggedIn() ? true : router.parseUrl('/login');
};

Guard types: canActivate, canActivateChild, canDeactivate (e.g., "unsaved changes" prompt), canMatch, resolve (pre-fetch data before route loads).

Resolvers (pre-fetch data):

TypeScript
export const userResolver: ResolveFn<User> = (route) => {
  const userService = inject(UserService);
  return userService.getUser(route.paramMap.get('id')!);
};

10. Forms

Angular offers two approaches.

Template-Driven Forms

HTML
<form #userForm="ngForm" (ngSubmit)="onSubmit(userForm.value)">
  <input name="email" ngModel required email #email="ngModel">
  <div *ngIf="email.invalid && email.touched">Invalid email</div>
  <button [disabled]="userForm.invalid">Submit</button>
</form>
  • Simple, good for basic forms
  • Logic lives mostly in the template
  • Uses FormsModule

Reactive Forms (recommended for complex/testable forms)

TypeScript
this.form = this.fb.group({
  email: ['', [Validators.required, Validators.email]],
  password: ['', [Validators.required, Validators.minLength(6)]],
  address: this.fb.group({
    city: [''],
    zip: ['']
  })
});
HTML
<form [formGroup]="form" (ngSubmit)="onSubmit()">
  <input formControlName="email">
  <div *ngIf="form.get('email')?.invalid && form.get('email')?.touched">
    Email is required and must be valid
  </div>
  <div formGroupName="address">
    <input formControlName="city">
  </div>
  <button [disabled]="form.invalid">Submit</button>
</form>
  • Model defined in TypeScript → more testable and predictable
  • Uses ReactiveFormsModule
  • Supports FormArray for dynamic list of controls

Custom Validator:

TypeScript
export function noSpecialChars(control: AbstractControl): ValidationErrors | null {
  const invalid = /[^a-zA-Z0-9]/.test(control.value);
  return invalid ? { specialChars: true } : null;
}

Async Validator (e.g., check username availability):

TypeScript
export function uniqueUsernameValidator(userService: UserService): AsyncValidatorFn {
  return (control: AbstractControl) =>
    userService.checkUsername(control.value).pipe(
      map(taken => (taken ? { usernameTaken: true } : null))
    );
}

Reactive vs Template-driven — the classic interview comparison:

Reactive Template-driven
Explicit, defined in class Implicit, defined in template
Synchronous access to form model Asynchronous
Easier unit testing Harder to test
Better for complex/dynamic forms Better for simple forms
Immutable data model Mutable

11. HTTP Client & Observables (RxJS)

Basic HTTP calls:

TypeScript
constructor(private http: HttpClient) {}

getPosts(): Observable<Post[]> {
  return this.http.get<Post[]>('/api/posts');
}

createPost(post: Post) {
  return this.http.post<Post>('/api/posts', post);
}

HTTP Interceptors (e.g., attach auth token):

TypeScript
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).getToken();
  const cloned = req.clone({ setHeaders: { Authorization: `Bearer ${token}` } });
  return next(cloned);
};

RxJS Operators commonly asked about:

TypeScript
searchInput$.pipe(
  debounceTime(300),
  distinctUntilChanged(),
  switchMap(term => this.searchService.search(term))
).subscribe(results => this.results = results);
  • map — transform emitted values
  • filter — filter emitted values
  • switchMap — cancels previous inner observable, switches to new one (best for search-as-you-type, avoids race conditions)
  • mergeMap — runs all inner observables concurrently
  • concatMap — runs inner observables sequentially, one after another
  • exhaustMap — ignores new emissions while current inner observable is active (good for preventing double form submits)
  • debounceTime — waits for a pause in emissions before emitting
  • distinctUntilChanged — skips consecutive duplicate values
  • catchError — handles errors within the stream without breaking it
  • combineLatest / forkJoin — combine multiple observables

switchMap vs mergeMap vs concatMap vs exhaustMap — interview must-know:

Operator Behavior Use case
switchMap Cancels previous, keeps latest Autocomplete search
mergeMap Runs all in parallel Independent parallel requests
concatMap Queues, runs in order Sequential API calls order matters
exhaustMap Ignores new while busy Prevent duplicate submit clicks

Handling errors:

TypeScript
this.http.get('/api/data').pipe(
  catchError(err => {
    console.error(err);
    return of([]); // fallback value
  })
).subscribe(data => this.data = data);

Unsubscribing — the async pipe (preferred, auto-unsubscribes):

HTML
<div *ngIf="user$ | async as user">{{ user.name }}</div>
TypeScript
user$ = this.userService.getUser();

12. Change Detection

Angular checks the component tree top-down to sync the DOM with data whenever an event, HTTP response, or timer fires (via Zone.js patching async APIs).

Two strategies:

  • Default — checks every component in the tree on every event
  • OnPush — only checks a component when:
  • An @Input() reference changes
  • An event originates from within the component (or a child)
  • An Observable bound via async pipe emits
  • Manually triggered via ChangeDetectorRef
TypeScript
@Component({
  selector: 'app-list',
  changeDetection: ChangeDetectionStrategy.OnPush,
  ...
})

OnPush is a major performance lever — use immutable data patterns (return new objects/arrays instead of mutating) so Angular detects the reference change.

Manually controlling change detection:

TypeScript
constructor(private cdr: ChangeDetectorRef) {}

updateData() {
  this.data = newData;
  this.cdr.markForCheck(); // schedule check for OnPush component
}

detachAndCheckManually() {
  this.cdr.detach();   // stop automatic detection
  this.cdr.detectChanges(); // manual trigger
}

Zone.js — patches async browser APIs (setTimeout, promises, DOM events) so Angular knows when to run change detection. Angular is moving toward zoneless change detection (using Signals) to reduce overhead.

13. Signals (Angular 16+)

Signals are a new reactive primitive that track dependencies automatically and update only what's needed — a step toward zoneless, fine-grained reactivity.

TypeScript
export class CounterComponent {
  count = signal(0);
  doubleCount = computed(() => this.count() * 2);

  increment() {
    this.count.update(c => c + 1);
  }

  constructor() {
    effect(() => console.log(`Count changed: ${this.count()}`));
  }
}
HTML
<p>{{ count() }}</p>
<p>Double: {{ doubleCount() }}</p>
<button (click)="increment()">+</button>
  • signal() — creates a writable reactive value
  • computed() — derived, read-only signal that auto-recalculates
  • effect() — runs side effects when dependent signals change
  • Signals notify only the components using them — avoids checking the whole tree like Zone.js-based CD does

Signal Inputs/Outputs (Angular 17.1+):

TypeScript
name = input<string>('');       // signal-based @Input
nameChange = output<string>();  // signal-based @Output

Interview point: "Why Signals over RxJS?" — Signals are simpler for synchronous state and integrate directly with change detection without needing subscriptions; RxJS remains better for complex async streams (HTTP, websockets, combining multiple async sources). They're complementary, not replacements — toSignal() and toObservable() bridge the two.

14. Standalone Components (Angular 14+, default since v17)

Standalone components/directives/pipes don't need an NgModule — they declare their own dependencies directly.

TypeScript
@Component({
  selector: 'app-user-card',
  standalone: true,
  imports: [CommonModule, RouterLink],
  template: `<a [routerLink]="['/user', id]">{{ name }}</a>`
})
export class UserCardComponent {
  @Input() name!: string;
  @Input() id!: number;
}

Bootstrapping without a root module:

TypeScript
bootstrapApplication(AppComponent, {
  providers: [provideRouter(routes), provideHttpClient()]
});

Why it matters: simplifies the mental model (no more NgModules boilerplate), improves tree-shaking, and is now the CLI default for new projects.

15. State Management (NgRx)

For large apps with complex shared state, NgRx implements the Redux pattern using RxJS.

Core pieces: Store (single source of truth), Actions (events), Reducers (pure functions producing new state), Selectors (derive/query state), Effects (handle side effects like HTTP calls).

TypeScript
// actions
export const loadUsers = createAction('[User] Load Users');
export const loadUsersSuccess = createAction(
  '[User] Load Users Success',
  props<{ users: User[] }>()
);

// reducer
export const userReducer = createReducer(
  initialState,
  on(loadUsersSuccess, (state, { users }) => ({ ...state, users }))
);

// effect
loadUsers$ = createEffect(() =>
  this.actions$.pipe(
    ofType(loadUsers),
    switchMap(() => this.userService.getUsers().pipe(
      map(users => loadUsersSuccess({ users }))
    ))
  )
);

// selector
export const selectAllUsers = (state: AppState) => state.users.list;

// component usage
this.users$ = this.store.select(selectAllUsers);
this.store.dispatch(loadUsers());

When to use NgRx vs simple services: Use plain services + BehaviorSubject for small/medium apps. Reach for NgRx when state is shared across many unrelated components, needs time-travel debugging, or has complex async flows — the boilerplate cost is worth it only at that scale.

16. Performance Optimization

  • OnPush change detection + immutable data
  • trackBy in *ngFor / track in @for
  • Lazy loading feature modules/routes
  • Standalone components to reduce bundle size via better tree-shaking
  • Pure pipes instead of function calls in templates ({{ getValue() }} re-runs every CD cycle; a pipe only re-runs when inputs change)
  • async pipe to auto-unsubscribe and let Angular manage subscription lifecycle
  • Virtual scrolling (@angular/cdk/scrolling) for long lists
  • Preloading strategy for lazy routes: PreloadAllModules loads lazy modules in the background after initial load
  • ChangeDetectorRef.detach() for components that rarely change
  • Web Workers for CPU-heavy computations off the main thread
  • Ahead-of-Time (AOT) compilation — compiles templates at build time instead of runtime, catches template errors early, and produces smaller/faster bundles (this is default in production builds)

17. Testing

Angular uses Jasmine (test framework) + Karma (test runner) by default; many teams also use Jest.

Component test with TestBed:

TypeScript
describe('UserCardComponent', () => {
  let fixture: ComponentFixture<UserCardComponent>;
  let component: UserCardComponent;

  beforeEach(async () => {
    await TestBed.configureTestingModule({
      declarations: [UserCardComponent]
    }).compileComponents();

    fixture = TestBed.createComponent(UserCardComponent);
    component = fixture.componentInstance;
  });

  it('should emit selected event on click', () => {
    spyOn(component.selected, 'emit');
    component.user = { name: 'Alice', email: 'a@x.com' };
    component.onSelect();
    expect(component.selected.emit).toHaveBeenCalledWith('Alice');
  });
});

Testing a service with HTTP mocking:

TypeScript
beforeEach(() => {
  TestBed.configureTestingModule({
    imports: [HttpClientTestingModule],
    providers: [UserService]
  });
  httpMock = TestBed.inject(HttpTestingController);
  service = TestBed.inject(UserService);
});

it('should fetch users', () => {
  service.getUsers().subscribe(users => expect(users.length).toBe(2));
  const req = httpMock.expectOne('/api/users');
  req.flush([{ name: 'A' }, { name: 'B' }]);
});

Key terms: TestBed (configures a testing module), ComponentFixture (wraps component + DOM for inspection), fixture.detectChanges() (triggers CD in tests), spies (mock method calls), HttpTestingController (intercepts HTTP calls in tests).

19. Security

  • XSS protection — Angular auto-sanitizes values bound via interpolation/property binding. Avoid innerHTML binding with untrusted content; if unavoidable, use DomSanitizer.sanitize().
  • bypassSecurityTrustHtml / bypassSecurityTrustUrl — explicitly mark content as trusted (use with extreme caution, only for known-safe sources).
  • CSRF protection — Angular's HttpClient automatically reads an XSRF token from a cookie and sends it as a header on same-origin requests, working with server-side CSRF middleware.
  • Route guards for authorization — but note: guards prevent client-side navigation; actual authorization must be enforced server-side too.

20. Common Tricky Interview Questions

Q: What's the difference between constructor and ngOnInit? constructor is a TypeScript/JS class feature used for basic initialization and DI — @Input() values are NOT yet available. ngOnInit is an Angular lifecycle hook that runs after Angular sets the initial input properties, so it's the right place for logic depending on @Input() data or API calls.

Q: What happens if you don't unsubscribe from an Observable? The subscription keeps the component/service alive in memory even after the component is destroyed (if the observable is long-lived, like interval or a Subject), causing a memory leak and potentially firing callbacks against a destroyed component's stale state.

Q: Difference between Subject, BehaviorSubject, ReplaySubject, AsyncSubject?

Type Behavior
Subject No initial value; only emits to subscribers after they subscribe
BehaviorSubject Requires initial value; always emits the current value to new subscribers
ReplaySubject Replays a configurable number of past emissions to new subscribers
AsyncSubject Only emits the last value, and only when the source completes

Q: What is the difference between ViewChild and ContentChild? ViewChild queries elements defined in the component's own template. ContentChild queries elements projected into the component from a parent via <ng-content>.

Q: Explain Angular's compilation: JIT vs AOT.

  • JIT (Just-In-Time) — compiles templates in the browser at runtime; used historically in dev mode; slower startup.
  • AOT (Ahead-Of-Time) — compiles templates during the build step into efficient JS; smaller bundles, faster rendering, catches template errors at build time. Default for production and, since Angular 9 (Ivy), for dev too.

Q: What is Ivy? Ivy is Angular's rendering engine/compiler (default since Angular 9) that compiles each component independently, enabling better tree-shaking, smaller bundles, faster rebuilds, and improved debugging compared to the older View Engine.

Q: How does Angular detect that data has changed for OnPush components when mutating an array/object directly? It doesn't — mutating in place keeps the same reference, so OnPush won't see a change. You must return a new reference (e.g., this.items = [...this.items, newItem]) so Angular's reference check finds the difference.

Q: What's the difference between a Service and a Component? A Component controls a view (template + logic tied to UI). A Service holds reusable business logic/data-access code with no UI, shared across components via DI.

Q: Difference between Observable and Promise?

Observable Promise
Lazy (executes only on subscribe) Eager (executes immediately)
Can emit multiple values over time Resolves once
Cancellable (unsubscribe) Not cancellable
Rich operator set (map, filter, retry...) Limited (.then/.catch)

Q: What is a pure pipe vs impure pipe, and why does it matter for performance? Covered in Section 6 — pure pipes only re-execute on reference change of inputs, impure pipes run every change-detection cycle, which can be expensive if overused (e.g., filtering large arrays on every keystroke).

Q: What's the purpose of NgZone? NgZone lets you run code inside or outside Angular's zone. Running code with ngZone.runOutsideAngular() is useful for high-frequency events (e.g., mousemove, animations) that don't need to trigger Angular's change detection, improving performance.

Q: How do you communicate between two unrelated (sibling) components? Through a shared service using a Subject/BehaviorSubject as an event bus, since there's no direct parent-child @Input/@Output relationship.

TypeScript
@Injectable({ providedIn: 'root' })
export class MessageService {
  private messageSource = new BehaviorSubject<string>('');
  currentMessage$ = this.messageSource.asObservable();
  changeMessage(msg: string) { this.messageSource.next(msg); }
}

Component metadata:   selector, template/templateUrl, styleUrls, standalone, changeDetection
Lifecycle order:      ngOnChanges → ngOnInit → ngDoCheck → ngAfterContentInit →
                       ngAfterContentChecked → ngAfterViewInit → ngAfterViewChecked → ngOnDestroy
Forms modules:        FormsModule (template-driven) | ReactiveFormsModule (reactive)
Change detection:     ChangeDetectionStrategy.Default | OnPush
Key RxJS operators:   map, filter, switchMap, mergeMap, concatMap, exhaustMap,
                       debounceTime, distinctUntilChanged, catchError, combineLatest, forkJoin
Signals API:          signal(), computed(), effect(), input(), output()
Testing stack:        Jasmine + Karma (default) / Jest (common alt), TestBed, HttpTestingController
CLI essentials:       ng new, ng generate, ng serve, ng build, ng test

Final Interview Tips

  • Be ready to explain trade-offs, not just definitions (e.g., "OnPush vs Default," "NgRx vs services," "Reactive vs Template-driven forms").
  • Practice writing a small reactive form with custom validation live — it's one of the most common practical exercises.
  • Know why something exists (e.g., why trackBy matters, why unsubscribing matters) — interviewers probe reasoning, not memorized syntax.
  • Brush up on the latest Angular direction: standalone components, Signals, and the new @if/@for control flow — many interviews now ask about these explicitly since they're the modern default.
