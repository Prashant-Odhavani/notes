How this handbook is ordered

Read it front to back and every topic builds on the one before it.

C# → OOP → SOLID → LINQ → advanced C# → the .NET platform → ASP.NET Core → databases → EF Core → testing → architecture → cloud and DevOps → interview practice.

Three ways to use it

MODE 1
Learn the path

Start at Part 1 and work forward. Each concept goes in simple terms → why it exists → small example → how it works → what goes wrong in production.

MODE 2
Revise fast

Every page opens with Quick revision. Core ideas get In simple terms, Remember this and Key takeaways boxes. Rapid revision collects them all.

MODE 3
Practise out loud

Questions are collapsed. Read one, answer it aloud, then expand. Answers are written as speech — what you'd actually say — plus what the interviewer is checking and the likely follow-ups.

Version context

Examples target .NET 8/9 and C# 12/13. Where behaviour changed meaningfully across versions (EF Core, ASP.NET Core hosting, Angular, React) the version is stated inline. Cloud limits and pricing move constantly — treat specific numbers as “order of magnitude, verify before quoting”, and explain the mechanism in an interview.

The learning path

Nine parts, thirty-seven topics. Prerequisites always come first: you will not meet async/await before the type system, or EF Core before SQL, or microservices before architecture.

One weekend (already strong, need recall)

  • Rapid revision end to end — flag anything you can't explain in 60 seconds.
  • Senior-level questions and red flags.
  • Two designs from system design, spoken aloud, timed at 40 minutes.
  • Three scenarios from scaling scenarios — one API, one database, one messaging.

Long term (no interview booked)

One section a week, in order. The value is in the “when not to use this” and “what breaks in production” parts — that's the material that turns into real engineering judgement rather than interview trivia, and it's exactly what a senior interviewer probes for.

Project files

The handbook tracks its own state so work can continue across sessions without relying on chat history:

  • PROJECT_STATUS.md — what's complete, what's next, known gaps.
  • CONTENT_MAP.md — every page, its scope, and the concepts it owns (prevents duplication).
  • STYLE_GUIDE.md — page template, HTML conventions, tone and depth rules.
  • DECISIONS.md — architectural and editorial decisions with rationale.
  • assets/nav-data.js — the structural source of truth. node tools/build-index.mjs rebuilds search and validates links; node tools/check-highlight.mjs validates every code block.
