C# Advanced: Memory, Async & Concurrency

This is the section that separates a mid-level from a senior C# developer. Not because it's obscure — because it's where production problems actually come from.

🔴 Advanced 🔥 Must know ⭐ Senior-level
Quick revision
  • The GC is generational: most objects die young, and collecting them is cheap. Objects that survive get promoted and become expensive.
  • async is about not blocking a thread while waiting. It is not about making things faster.
  • .Result and .Wait() on an async call are how you deadlock a web app.
  • Concurrency = several things in progress. Parallelism = several things executing at once. Not the same problem.
  • A memory leak in .NET is almost always something long-lived holding a reference to something short-lived.
  • Measure before optimising. BenchmarkDotNet, not a stopwatch and a hunch.

What interviewers are looking for here ⭐ Senior-level

In simple terms

These questions are a proxy for "have you debugged something hard in production?"

Anyone can define async. Far fewer can explain why an app deadlocked, or why memory grew by 200 MB a day and then stopped growing after one line changed.

The questions that come up most, and what each is really probing:

QuestionWhat it's really testing
"What does async actually do?"Whether you think it creates threads (it doesn't)
"Why does .Result deadlock?"Whether you understand the synchronisation context
"How would you find a memory leak?"Whether you've ever taken a dump and looked at roots
"When would you use a lock?"Whether you know the cheaper alternatives first
"Is this code thread-safe?"Whether you can spot a read-modify-write
"How do you know it's faster?"Whether you measure or guess
Senior signal

The strongest answers in this area are stories with a mechanism.

"Memory grew steadily and never recovered. I took a dump, looked at what was rooting the large object set, and found an event handler that was never unsubscribed — the publisher was a singleton, so every request's subscriber stayed alive forever."

That answer proves the knowledge in a way no definition can.

Three misconceptions to clear up first

These come up constantly, and getting them right early makes the rest of the section easier.

People thinkActually
"async makes code run on another thread" No. async releases the current thread while waiting for I/O. No new thread is created. For CPU work you need Task.Run, which is a different thing.
"The GC is slow, so I should avoid allocating" Gen 0 collection is very cheap. What's expensive is objects surviving to Gen 2 and the large object heap. Short-lived garbage is close to free.
"C# is managed, so it can't leak" It leaks constantly — just differently. Anything reachable from a long-lived root can't be collected. Static collections, events and captured closures are the usual culprits.
